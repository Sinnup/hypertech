# HT-CD1878 — Approval stall + Slack status fix

- **Scenario**: fix
- **Agents**: validation_gate, context_packer
- **Branch**: feature/HT-CD1878 (stacked on feature/HT-39C515)
- **Created**: 2026-06-25 19:10 UTC
- **Status**: in_progress

## Summary
After a human approved a compliance/architect escalation, the pipeline did not
continue and the Slack channel went silent. Root causes:

1. The escalation checkpoint was never saved, *and* even if it were, the normal
   completion path (`human_escalation → END`) deleted any checkpoint — so there
   was nothing to resume.
2. The Slack approval button only recorded the decision in memory; it never
   triggered a resume.
3. `context_packer` ran silently, so no status appeared between agents.

## Changes
- **core/events/graph_events.py**:
  - Save a checkpoint on *every* validation_gate pass, including escalation
    (current_agent + agent_plan_index point at the escalated agent, so resume
    re-evaluates it and picks up the stored approval).
  - Do **not** delete the checkpoint when the run ends escalated — keep it so an
    approval / `/resume` can continue the pipeline.
- **core/notifications/slack_commands.py**: `/slack/interactive` now triggers
  `_resume_pipeline_async()` on `approved` / `changes_requested` (guarded on a
  checkpoint existing); a rejection stays terminal. Posts resume status to Slack.
- **agents/context_packer/agent.py**: post `slack.status()` when packing context
  and when handing off to the next agent — the channel no longer goes quiet.

## Verification
`uv run pytest tests/e2e/test_approval_resume.py` → escalation checkpoint kept,
clean run deletes it. Full self-approving compliance run covered in final
validation (HT-5F1674) via `HITL_AUTOPILOT`.
