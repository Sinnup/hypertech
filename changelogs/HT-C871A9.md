# HT-C871A9 — Pipeline execution correctness (state growth + gate loop)

- **Scenario**: fix
- **Agents**: (graph/state infrastructure)
- **Branch**: feature/HT-C871A9 (stacked on feature/HT-20911B)
- **Created**: 2026-06-25 20:25 UTC
- **Status**: in_progress

## Summary
Real end-to-end runs (enabled by HT-20911B's LangSmith standardization) exposed
two pre-existing latent bugs that stopped pipelines completing cleanly:

1. **Exponential state growth.** The `operator.add` list channels
   (`agent_messages`, `pending_questions`, `pending_answers`, `human_approvals`)
   combined with agents returning the *full* state meant the reducer concatenated
   each list onto itself every node — doubling per step (8 nodes → ~510 items,
   GB-scale state, LangSmith rejected 26MB+ trace payloads).
2. **context_packer routing loop.** context_packer is registered via `@register`,
   so the "every agent → validation_gate" loop gave it a second static edge to
   the gate on top of its conditional `_plan_router` edge. The fan-out re-ran the
   gate on context_packer forever → `GraphRecursionError`.

## Changes
- **core/state/pipeline_state.py**: the four list channels now use
  `_keep_latest` (last-write-wins) instead of `operator.add`. Correct because
  agents read-modify-write the full list in the shared state and run
  sequentially (no parallel writes). Removed the now-unused `operator` import.
- **core/graph/workflow.py**: exclude infrastructure nodes (orchestrator,
  context_packer, validation_gate, human_escalation) from the agent→gate edge
  loop so context_packer routes only via `_plan_router`.
- **tests/e2e/test_state_growth.py**, **tests/e2e/test_graph_wiring.py** (new):
  regression tests — linear (not exponential) growth; context_packer has no edge
  to validation_gate.
