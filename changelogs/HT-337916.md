# HT-337916 — Stop control for running pipelines/commands

- **Scenario**: feature
- **Branch**: feature/HT-337916
- **Created**: 2026-06-26 04:30 UTC
- **Status**: completed

## Summary
Part 1 of the progress-visualizer feature: a way to stop a running pipeline from
/viz or Slack, halting gracefully at the next node boundary (resumable).

## Changes
- **core/control/cancel.py** (new): `request_stop / is_stop_requested / clear_stop`
  — in-memory set + `.hypertech/cancel/{ticket}` file flag (cross-process).
- **core/events/graph_events.py:stream_pipeline**: after each node, if stop
  requested → save checkpoint, set status=stopped, emit `agent_end` +
  `pipeline_stopped`, clear the flag, break. Checkpoint kept (resumable).
- **core/server/viz_routes.py**: `POST /viz/stop?ticket_id=…`.
- **core/notifications/slack_commands.py**: `/stop HT-XXXXXX` command + a
  `value:"stop"` block-action handler (for a 🛑 Stop button).
- **static/viz.html**: 🛑 Stop button (shown when a ticket is active) → POST
  /viz/stop; handles `pipeline_stopped`.
