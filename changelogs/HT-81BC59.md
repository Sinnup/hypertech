# HT-81BC59 — KB circuit breaker degrades immediately (no 120s approval wait)

- **Scenario**: fix
- **Agents**: ba_compliance
- **Branch**: feature/HT-81BC59
- **Created**: 2026-06-26 03:40 UTC
- **Status**: completed

## Summary
With the circuit-breaker timeout now working (HT-F3FBAC), a wedged ChromaDB still
made `ba_compliance` appear hung: `_query_kb`'s breaker used the default
`require_approval=True`, so on the 10 s timeout it posted a circuit-breaker
approval to Slack and waited **120 s** before falling back. A missing knowledge
base does not need a human to approve "proceed without regulatory context" — it
should degrade immediately.

## Changes
- **agents/ba_compliance/agent.py**: `_query_kb` circuit breaker now
  `require_approval=False` → on KB timeout/failure it falls back to an empty KB
  in ~10 s (posts "ChromaDB unavailable") instead of a 120 s approval wait.

## Verification
With ChromaDB deliberately wedged (get_database hanging), `ba_compliance.run()`
completes in ~16 s (status=degraded) instead of hanging — KB timeout (10 s) +
immediate fallback + LLM. Full e2e suite green.
